# Template-Driven Governance Migration (P0)

## Decision

The target production architecture is:

```text
HARA Template → Template Role Contract → MethodContract
Project Input → grounded ProjectFacts
MethodContract + ProjectFacts → deterministic HARA evaluation
```

The Template Role Contract is generated by the system. It binds semantic role
locations to an immutable `template_hash` and contains no copied engineering
rules. It is not a third customer-maintained business input. Unambiguous
templates compile automatically. Human confirmation is requested only for an
ambiguous role and is invalid for any different workbook hash.

## Migration Guardrails

- Existing Domain and legacy runtimes remain operational only for comparison
  until Application cutover.
- No new business rule may be added to the migration-only runtime.
- No Domain rule is copied into the MethodContract foundation.
- Provider retry, schema retry, cache recovery, and checkpoint recovery remain
  valid technical recovery mechanisms.
- Missing facts, missing rules, rule conflicts, and unresolved role ambiguity
  remain `PENDING`/not-ready and never fall back to old engineering values.
- ASIL remains a deterministic lookup from the active template's discovered
  matrix; it is never copied into Python or configuration.

## P0 Contract Boundary

P0 implements structural workbook scanning, canonical role discovery,
template-hash-bound manifests, diagnostics, and a non-executable
`MethodContract` foundation. The foundation explicitly reports
`engineering_rules_compiled=false`; full rule parsing and evaluation belong to
the next phases.

## P0-2 Full Template Compiler

P0-2 extends the foundation without switching production runtime. The
hash-bound role locations now compile through role-specific parsers into a
typed Rule IR and full `MethodContract`. Normative rules, criteria, examples,
assumptions/instructions, and references retain different strengths. Every
executable normative rule has an exact workbook `SourceRef`.

The current workbook compiles as `READY_WITH_WARNINGS` with
`engineering_rules_compiled=true`. Warnings preserve unresolved source
semantics (including the meaning of severity variable `v`, alternative
severity results, exposure method selection, workflow coordinate mismatches,
and NA versus QM). None is silently repaired from the migration-only Domain
runtime.

Role discovery priority is:

1. explicit metadata / named ranges / structured tables that satisfy the role;
2. structural signature;
3. header semantic signature;
4. bounded LLM classification of existing candidates;
5. fail closed.
